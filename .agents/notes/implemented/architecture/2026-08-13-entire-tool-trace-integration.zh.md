# Agent Note: 规范工具追踪与可选 Entire 检查点

Status: implemented

[English](2026-08-13-entire-tool-trace-integration.md) | 中文

## 问题

持久会话日志已经记录模型消息、根级与嵌套工具调用/结果、审批、压缩、用量和谱系，但它无法说明策略是否准入一次调用，也无法说明已注册的工具主体是否真的运行。外部检查点工具还需要已提交事实，但不能成为第二个运行时权威、解析依赖后端的持久化产物，或影响模型体验。

## 决策

`SessionEvent` 继续作为规范追踪。工具注册表围绕现有调用/结果记录追加三个狭窄的纯日志事件：`tool/policy-result`、`tool/body-start` 和 `tool/body-end`。它们携带稳定的调用/根级身份、有界结果/来源枚举和一个中止位，不携带策略说明、错误文本、参数或结果主体。既有 `approval/asked` 和 `approval/decided` 事件仍是唯一的审批审计。运行时不变量强制调用先于策略、允许策略先于主体、主体开始/结束配对、结果终止、根级/嵌套身份，以及并行调用的有效交错。

Web UI 和 SDK 使用同一条持久流。时长由事件时间戳派生，因此不新增执行遥测流。经过验证与 post-execute 策略后，`tool/result` 仍是面向模型结果的权威记录；主体结束只描述已注册主体的 promise。

基础组合包挂载休眠的 Entire bridge。只有适配器自有的克隆本地 `.entire/dsh-hooks.json` 标记才能激活它。bridge 从已提交事件投影有界的规范化伴随文件，并调用使用固定参数的 Entire 生命周期钩子；失败只产生诊断。可执行适配器属于上游 `entireio/external-agents`，不属于本仓库。其当前 `codex/dsh-adapter` 实现已通过协议/合规覆盖，但在 bridge 落地且端到端捕获通过前，真实 Harness-to-Entire 生命周期仍未验证。

## 隐私边界

默认导出保留真实提示词、已提交的 assistant 文本与用量、根级/嵌套工具调用/结果、策略与审批事实、主体时序、压缩和谱系。它排除原始分片、请求头、系统提示词、完整工具 schema、环境数据、凭据、不透明适配器状态和注入的内部上下文。凭据键掩码和逐结果字节上限只是尽力而为，不提供保密保证。严格模式还会排除工具输入/结果和类似推理的 assistant 内容。用户必须使用独立的私有检查点远端，并在首次推送前于本地检查。

## 曾考虑的替代方案

- **第二条追踪流或 HTTP 导出器**：拒绝，因为消费者可能看到与 `SessionEvent` 不同的顺序和持久性，而且导出器会给 agent 工作增加网络与失败边界。
- **在适配器中解析原生会话产物**：拒绝，因为持久化依赖后端且默认压缩；规范化伴随文件才是有界的兼容性约定。
- **重复记录审批等待事件**：拒绝，因为现有 asked/decided 对已经提供持久等待区间。
- **由 Harness 安装适配器，或指导用户不经审查直接克隆并运行**：拒绝，因为 Harness 不得安装外部可执行文件，也不能将未经审查的供应链行为正常化。

## 后果

- 同一条可回放流驱动模型文本记录、Web 追踪、SDK 通知和可选检查点投影。
- 无需持久化错误文本，就能区分拒绝、取消、未知工具、包装层短路、抛出和中止路径。
- bridge 不影响提示词、token 或 KV Cache，也不能让成功的 Harness 轮次依赖 Entire。
- Entire 检查点创建是可选的，成功的 Harness 运行并不保证检查点创建；用户指南会继续明确当前适配器/bridge 生命周期验证状态。
